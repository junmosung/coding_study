# Codex Kotlin 실전 문법 문제 기획서

기본 문법 C01~C30 다음에 진행하는 두 번째 트랙입니다. 단순히 문법을 아는 단계를 넘어, 재사용 가능하고 안전한 Kotlin API를 설계하는 능력을 목표로 합니다.

## 트랙 범위

| 단계 | 문제 | 학습 목표 | 진입 조건 |
|---|---:|---|---|
| A · 기본 | C31~C38 | 함수 API와 실패 처리 방식을 Kotlin답게 표현 | 기본 문법 A·B 단계 완료 |
| B · 중급 | C39~C46 | 제네릭과 확장 기능으로 타입 안전한 API 작성 | nullable·컬렉션 체인에 익숙함 |
| C · 고급 | C47~C53 | 위임과 Sequence로 상태 및 실행 시점 제어 | 클래스·인터페이스·람다 이해 |
| D · 최고급 | C54~C60 | 도메인 타입, 상태 머신, DSL을 조합 | 실전 문법 A~C 단계 완료 |

## 이 트랙에서 익혀야 할 습관

- 호출하는 쪽이 읽기 좋은 함수 시그니처를 먼저 설계합니다.
- 잘못된 인수, 실행 실패, 값 부재를 각각 `require`, `Result`, nullable 타입으로 구분합니다.
- 제네릭의 `in`과 `out`을 암기하지 않고 값이 들어오는지 나가는지를 기준으로 판단합니다.
- 상속보다 위임이 자연스러운 상황을 구별합니다.
- 큰 데이터 흐름에서는 List와 Sequence의 실행 시점 및 중간 객체 차이를 설명합니다.
- 확장 함수, 연산자, 중위 함수, DSL은 단순히 짧게 쓰기 위해 사용하지 않습니다.

## A · 기본 — 함수 API와 실패 처리

| 문제 | 기획 명세 | 반드시 캐치할 문법 |
|---|---|---|
| C31 탐사 옵션 생성 | 기본값이 있는 `createOptions(destination, retries, safeMode)`를 작성하고 이름 있는 인수로 일부 옵션만 변경 | 기본 인수, 이름 있는 인수, 호출부 가독성 |
| C32 주파수 일괄 등록 | 첫 주파수와 가변 개수의 추가 주파수를 받아 중복 없는 정렬 목록 반환 | `vararg`, 스프레드 연산자 `*`, 배열과 List 차이 |
| C33 좌표 구조 분해 | `Coordinate3D`를 구조 분해해 거리 및 표시 문자열 계산 | `data class`, `componentN`, 구조 분해 선언 |
| C34 발사 조건 검증 | 잘못된 외부 인수와 객체 내부 상태 오류를 서로 다른 방식으로 검증 | `require`, `check`, 지연 메시지 람다 |
| C35 안전한 계산 결과 | 0으로 나누기와 숫자 파싱 실패를 `Result<Int>`로 반환 | `runCatching`, `getOrElse`, `exceptionOrNull` |
| C36 통신 예외 분류 | 여러 예외를 하나의 `try` 표현식에서 사용자 메시지로 변환 | `try` 표현식, 다중 `catch`, `finally`, 사용자 예외 |
| C37 지연 초기화 지도 | 비용이 큰 행성 지도를 처음 사용할 때 한 번만 생성 | `by lazy`, 초기화 시점, 캐시되는 값 |
| C38 장비 연결 상태 | 초기화 이후에만 사용 가능한 장비 프로퍼티와 연결 여부 제공 | `lateinit`, `::property.isInitialized`, nullable과의 선택 기준 |

## 완료 기준

각 문제의 테스트 통과 외에도 다음 질문에 답할 수 있어야 합니다.

1. 같은 요구사항을 기본 문법으로만 풀었을 때보다 현재 API가 더 안전한 이유는 무엇인가?
2. 컴파일 시점에 막는 오류와 실행 시점에 처리하는 오류는 각각 무엇인가?
3. 사용한 고급 문법을 제거하는 편이 오히려 읽기 좋은 경우는 언제인가?
4. 입력, 출력, 실패 정책이 함수 시그니처에 얼마나 드러나는가?

## 후속 트랙

실전 문법 다음에는 외부 라이브러리가 필요한 **코루틴과 동시성**, 이후 **테스트와 애플리케이션 설계** 트랙으로 이어갑니다. 코루틴을 이 트랙에 섞지 않아 언어 및 표준 라이브러리 학습과 비동기 실행 모델 학습을 분리합니다.
